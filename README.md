# DiaAgent

DiaAgent — MVP учебного прототипа ИИ-агента для анализа питания и учебного расчёта болюсного инсулина при сахарном диабете 1 типа.

Текущая версия является MVP проекта: она показывает базовую архитектуру, интерфейс, расчёты, предупреждения безопасности, получение БЖУ продуктов через внешние API и локальную имитацию объяснения ИИ-агента. На следующем этапе планируется подключение реального ИИ через API.

Проект не является медицинским приложением и не является медицинским изделием. Все расчёты нужны только для демонстрации логики в рамках курсовой работы.

## Цель курсовой

Цель MVP проекта — показать, как можно объединить простой интерфейс, валидацию данных, получение БЖУ продуктов по внешнему API, расчётные функции, локальное объяснение результата и сохранение истории в SQLite.

Прототип использует только индивидуальные параметры, которые пользователь уже получил от медицинского специалиста. Он не подбирает коэффициенты и не заменяет врача.

## Возможности приложения

В MVP реализованы:

- ввод описания еды с массой продуктов, глюкозы в ммоль/л и индивидуальных коэффициентов;
- получение БЖУ продуктов через внешние API;
- расчёт болюса на еду;
- расчёт коррекционного болюса;
- учёт активного инсулина;
- предупреждения о потенциально опасных ситуациях;
- локальная имитация объяснения ИИ-агента без подключения к внешнему API;
- сохранение истории расчётов в SQLite;
- тесты для расчётов и правил безопасности.

## Источник БЖУ

Локального справочника продуктов в приложении нет. Пользователь описывает приём пищи в свободной форме, например `гречки 50 грамм, банан 120 г`, после чего приложение получает данные БЖУ через внешние API и рассчитывает белки, жиры, углеводы и калорийность по найденным данным.

Основной источник для типовых продуктов — All The Nutrients API. Для некоторых брендированных продуктов приложение может использовать Open Food Facts API как дополнительный источник. Значения БЖУ могут быть неполными или отличаться от конкретной упаковки продукта, поэтому перед использованием результата стоит сверять данные с этикеткой.

## Статус MVP и развитие

Сейчас DiaAgent работает как MVP без подключения к реальному API искусственного интеллекта. Модуль `llm_agent.py` формирует безопасное локальное объяснение результата по заранее заданной логике.

Дальнейшее развитие проекта предполагает подключение ИИ через API, чтобы агент мог давать более гибкие объяснения, анализировать рацион подробнее и помогать пользователю лучше понимать введённые данные. Даже после подключения API проект должен сохранять медицинские ограничения: расчёт остаётся учебным, не является назначением лечения и не заменяет врача.

## Формулы расчёта

Болюс на еду:

```text
meal_bolus = carbs_g / insulin_to_carb_ratio
```

Коррекционный болюс:

```text
correction_bolus = (current_glucose_mmol - target_glucose_mmol) / correction_factor_mmol
```

Если коррекционный болюс меньше 0, используется 0.

Итоговый учебный болюс:

```text
total_bolus = meal_bolus + correction_bolus - active_insulin
```

Если итоговый результат меньше 0, используется 0. Все результаты округляются до 2 знаков.

## Единицы измерения

Глюкоза в проекте измеряется только в ммоль/л. Поля, переменные и расчётные функции используют обозначение `mmol` или `ммоль/л`.

Проект не использует мг/дл.

## Медицинская безопасность

Расчёт не является медицинской рекомендацией. Приложение не назначает лечение, не предлагает делать инъекцию и не заменяет консультацию врача.

Не изменяйте лечение без консультации с врачом. При низкой или значительно повышенной глюкозе следуйте индивидуальному плану, назначенному медицинским специалистом.

## Запуск приложения

Команды запуска выполняются из папки `diaagent`. Если вы находитесь в корне репозитория, сначала выполните:

```bash
cd diaagent
```

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m streamlit run app.py
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m streamlit run app.py
```

Важно запускать Streamlit через активированное виртуальное окружение или через `python -m streamlit run app.py`. Это помогает не использовать глобальные пакеты Python, которые могут быть установлены для другой архитектуры процессора.

## Запуск тестов

```bash
pytest
```

## Частая ошибка на macOS

Если при запуске появляется ошибка вида `ImportError: ... pandas_parser ... incompatible architecture`, значит Python запустил `pandas`, установленный для другой архитектуры, например `x86_64` вместо `arm64`.

Для исправления используйте виртуальное окружение проекта:

```bash
cd diaagent
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
python -m streamlit run app.py
```

Если окружение уже создано, но ошибка осталась, пересоздайте его:

```bash
rm -rf .venv
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m streamlit run app.py
```
