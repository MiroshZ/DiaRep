# DiaAgent

DiaAgent — MVP учебного прототипа ИИ-агента для анализа питания и учебного расчёта болюсного инсулина при сахарном диабете 1 типа.

Текущая версия является MVP проекта: она показывает базовую архитектуру, современный веб-интерфейс без Streamlit, расчёты, предупреждения безопасности, получение БЖУ продуктов через внешние API, распознавание еды по фото через Gemini в Polza.ai и локальную имитацию текстового объяснения ИИ-агента.

Проект не является медицинским приложением и не является медицинским изделием. Все расчёты нужны только для демонстрации логики в рамках курсовой работы.

## Цель курсовой

Цель MVP проекта — показать, как можно объединить простой интерфейс, валидацию данных, получение БЖУ продуктов по внешнему API, расчётные функции, локальное объяснение результата и сохранение истории в SQLite.

Прототип использует только индивидуальные параметры, которые пользователь уже получил от медицинского специалиста. Он не подбирает коэффициенты и не заменяет врача.

## Возможности приложения

В MVP реализованы:

- ввод описания еды с массой продуктов, глюкозы в ммоль/л и индивидуальных коэффициентов;
- современный frontend на HTML, CSS и JavaScript;
- backend на FastAPI;
- распознавание еды и примерного веса по фото через Gemini 3.1 Flash-Lite через Polza.ai;
- получение БЖУ продуктов через внешние API;
- личный кабинет с локальным сохранением настроек Nightscout;
- автоматическое получение актуальной глюкозы из Nightscout при активном доступе;
- расчёт болюса на еду;
- расчёт коррекционного болюса;
- учёт активного инсулина;
- предупреждения о потенциально опасных ситуациях;
- локальная имитация объяснения ИИ-агента без подключения к внешнему API;
- сохранение истории расчётов в SQLite;
- тесты для расчётов и правил безопасности.

## Источник БЖУ

Локального справочника продуктов в приложении нет. Пользователь описывает приём пищи в свободной форме, например `гречки 50 грамм, банан 120 г`, после чего приложение получает данные БЖУ через внешние API и рассчитывает белки, жиры, углеводы и калорийность по найденным данным.

Основной источник для типовых продуктов — All The Nutrients API. Для некоторых брендированных продуктов приложение может использовать Open Food Facts API как дополнительный источник. Значения БЖУ могут быть неполными или отличаться от конкретной упаковки продукта, поэтому перед использованием результата стоит сверять данные с этикеткой.

## Интеграция Nightscout

В приложении есть блок `Личный кабинет`, где можно активировать доступ к интеграции и указать адрес Nightscout вместе с API key или read-only token. Ключ не хранится в коде и не должен попадать в git. В веб-версии профиль хранится в браузере пользователя через `localStorage`, а на сервер отправляется только во время запроса к Nightscout.

После привязки Nightscout главный расчёт берёт текущую глюкозу из `/api/v1/entries/current.json` или `/api/v1/entries/sgv.json`. Nightscout возвращает SGV в мг/дл, а приложение автоматически переводит значение в ммоль/л для расчёта.

Для внешних приложений лучше использовать read-only token с ограниченными правами, а не основной API secret.

## Распознавание еды по фото

В форме расчёта можно загрузить фото еды. Backend отправляет изображение в Polza.ai Chat Completions API, использует модель `google/gemini-3.1-flash-lite`, получает список видимых продуктов с примерным весом в граммах и автоматически подставляет результат в поле описания еды. После этого основной расчёт использует ту же логику БЖУ и болюса.

Ключ Polza.ai не хранится в коде и не должен попадать в git. Для работы функции нужно задать переменную окружения:

Вариант для локального запуска через `.env`:

```bash
cd diaagent
cp .env.example .env
```

После этого откройте `diaagent/.env` и укажите свой ключ Polza.ai. Файл `.env` добавлен в `.gitignore`, поэтому ключ не будет отправлен в репозиторий.

macOS / Linux:

```bash
export POLZA_AI_API_KEY=your_polza_key_here
```

Windows PowerShell:

```powershell
$env:POLZA_AI_API_KEY="your_polza_key_here"
```

Опционально можно переопределить модель, если в Polza.ai будет выбран другой совместимый идентификатор:

```bash
export GEMINI_MODEL=google/gemini-3.1-flash-lite
```

Без `POLZA_AI_API_KEY` сайт продолжит работать, но распознавание еды по фото будет возвращать ошибку настройки.

## Статус MVP и развитие

Сейчас DiaAgent работает как MVP: фото еды распознаётся через внешний ИИ API Polza.ai, а модуль `llm_agent.py` всё ещё формирует безопасное локальное объяснение результата по заранее заданной логике.

Дальнейшее развитие проекта предполагает расширение ИИ-части через API, чтобы агент мог давать более гибкие объяснения, анализировать рацион подробнее и помогать пользователю лучше понимать введённые данные. Даже после подключения API проект должен сохранять медицинские ограничения: расчёт остаётся учебным, не является назначением лечения и не заменяет врача.

## Формулы расчёта

Болюс на еду:

```text
meal_bolus = carbs_g / insulin_to_carb_ratio
```

Коррекционный болюс:

```text
correction_bolus = (current_glucose_mmol - target_glucose_mmol) / correction_factor_mmol
```

Если коррекционный болюс меньше 0, используется 0.

Итоговый учебный болюс:

```text
total_bolus = meal_bolus + correction_bolus - active_insulin
```

Если итоговый результат меньше 0, используется 0. Все результаты округляются до 2 знаков.

## Единицы измерения

Глюкоза в проекте измеряется только в ммоль/л. Поля, переменные и расчётные функции используют обозначение `mmol` или `ммоль/л`.

Проект не использует мг/дл.

## Медицинская безопасность

Расчёт не является медицинской рекомендацией. Приложение не назначает лечение, не предлагает делать инъекцию и не заменяет консультацию врача.

Не изменяйте лечение без консультации с врачом. При низкой или значительно повышенной глюкозе следуйте индивидуальному плану, назначенному медицинским специалистом.

## Запуск приложения

Команды запуска выполняются из папки `diaagent`. Если вы находитесь в корне репозитория, сначала выполните:

```bash
cd diaagent
```

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn web:app --reload
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn web:app --reload
```

После запуска сайт будет доступен по адресу `http://127.0.0.1:8000`.

## Деплой на Render

В корне репозитория есть файл `render.yaml`. Для деплоя можно подключить GitHub-репозиторий к Render и создать Blueprint/Web Service. Render использует:

```bash
pip install -r requirements.txt
uvicorn web:app --host 0.0.0.0 --port $PORT
```

В Render нужно добавить переменную окружения `POLZA_AI_API_KEY`. В `render.yaml` также указан `GEMINI_MODEL=google/gemini-3.1-flash-lite`.

## Частая ошибка на macOS

Если при запуске появляется ошибка вида `ImportError: ... incompatible architecture`, значит Python использует глобальные пакеты другой архитектуры, например `x86_64` вместо `arm64`.

Для исправления пересоздайте виртуальное окружение проекта:

```bash
rm -rf .venv
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn web:app --reload
```
